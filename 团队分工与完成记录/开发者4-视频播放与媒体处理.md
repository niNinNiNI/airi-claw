# 开发者 4 — 视频播放与媒体处理

## 概述

开发者 4 负责 AIRI Edge Agent 的**视频播放与媒体处理子系统**，包括视频文件扫描与播放列表管理、音视频流解码适配、PPA (Pixel Processor Accelerator) 硬件加速图像合成、LCD 显示驱动的适配集成。该子系统让 ESP32-P4 设备具备 SD 卡视频文件循环播放能力。

---

## 完成的核心模块

### 1. 视频播放引擎 (components/video_player/video_player.c)

#### 1.1 播放列表管理
- **视频文件扫描**：`scan_media_files()` — 递归扫描 SD 卡目录，识别 `.mp4` 和 `.avi` 文件
- **播放列表构建**：最大支持 50 个文件，存储完整路径
- **循环播放逻辑**：`video_task()` — 按序播放，播放完成后自动播放下一个，播完一轮从头开始
- **播放计数**：跟踪总播放次数（`total_play_count`）

#### 1.2 显示驱动集成
- **LCD 面板获取**：通过 `esp_board_manager_get_device_handle()` 获取 DPI LCD 面板句柄
- **帧缓冲区管理**：
  - 优先使用 DPI 面板的原生帧缓冲区（双缓冲）
  - 回退方案：在 PSRAM 中分配 RGB565 帧缓冲区（480×800×2 字节）
- **垂直同步 (VSync)**：`vsync_ready_callback()` — 通过 ISR 信号量实现逐帧同步，确保无撕裂渲染
- **显示仲裁**：`display_arbiter_acquire() / display_arbiter_release()` — 与 UI 系统协调显示资源使用

#### 1.3 播放控制流程
- **初始化**：`video_player_init()` — 获取 LCD 面板、分配帧缓冲、注册 VSync 回调
- **启动**：`video_player_start()` — 扫描 SD 卡、初始化音频设备、创建视频播放任务
- **停止**：`video_player_stop()` — 停止播放、清理资源、释放显示仲裁
- **播放状态检测**：通过 `app_stream_adapter_is_eos()` 检测流结束 + 帧计数稳定回退检测（5 次无变化判定结束）

#### 1.4 优雅降级
- SD 卡不可用：跳过视频播放，退回表情 UI
- 无视频文件：跳过播放
- 无音频设备：仅视频播放
- LCD 不支持：返回 `ESP_ERR_NOT_SUPPORTED`

### 2. 流媒体适配层 (components/video_player/app_stream_adapter.c / .h)

- **流适配器初始化**：`app_stream_adapter_init()` — 配置解码回调、帧缓冲区、音频设备
- **文件加载**：`app_stream_adapter_set_file()` — 加载视频文件并解析
- **媒体信息查询**：`app_stream_adapter_get_info()` — 返回宽、高、帧率、时长
- **播放控制**：`app_stream_adapter_start()` / `app_stream_adapter_stop()`
- **状态查询**：`app_stream_adapter_is_eos()` — 判断是否播放完成
- **统计收集**：`app_stream_adapter_get_stats()` — 返回已处理帧数

### 3. 音视频提取器 (components/video_player/app_extractor.c / .h)

- **文件提取初始化**：`app_extractor_open()` — 打开视频文件并初始化提取器
- **音视频帧提取**：`app_extractor_read_video_frame()` / `app_extractor_read_audio_frame()`
- **格式支持**：通过 `esp_extractor` 组件（预编译库）支持 MP4、AVI 等多种格式

### 4. PPA 硬件加速图像合成 (components/video_player/ppa_blend.c / .h)

- **PPA 硬件初始化**：使用 ESP32-P4 的 Pixel Processor Accelerator 硬件单元
- **图像混合**：`ppa_blend_overlay()` — 在视频帧上叠加 UI 元素（如表情动画）
- **色彩空间转换**：支持 RGB565 到 RGB888 等转换
- **缩放处理**：硬件加速的图像缩放

### 5. 音频输出集成

- **音频设备获取**：通过 `esp_board_manager_get_device_handle()` 获取 DAC 设备句柄
- **音量控制**：`esp_codec_dev_set_out_vol()` — 设置输出音量为 80%
- **条件编译**：通过 `CONFIG_VIDEO_PLAYER_AUDIO_ENABLE` 控制音频功能启用

### 6. 外部媒体提取器库 (components/esp_extractor/)

- **预编译库**：为多种 ESP 芯片架构提供预编译 `.a` 文件：
  - ESP32 / ESP32-C3 / ESP32-C6 / ESP32-P4 / ESP32-S2 / ESP32-S3
- **多格式支持**：
  - `esp_mp4_extractor.h` — MP4 容器格式
  - `esp_avi_extractor.h` — AVI 容器格式
  - `esp_flv_extractor.h` — FLV 流媒体格式
  - `esp_ts_extractor.h` — MPEG-TS 格式
  - `esp_hls_extractor.h` — HLS 直播流格式
  - `esp_ogg_extractor.h` — OGG 容器格式
  - `esp_wav_extractor.h` — WAV 音频格式
  - `esp_caf_extractor.h` — Core Audio 格式
  - `esp_audio_es_extractor.h` — 音频 ES 流
- **ID3 标签解析**：`esp_extractor_id3.h` — 提取音频元数据
- **数据缓存**：`data_cache.h` — 媒体数据的缓存管理
- **内存池**：`mem_pool.h` — 专用的内存分配器
- **提取器注册中心**：`esp_extractor_reg.h` — 动态注册/注销提取器

### 7. Kconfig 配置项

- `CONFIG_VIDEO_PLAYER_AUDIO_ENABLE` — 控制是否启用音频播放
- 视频播放器的编译开关

## 技术难点与解决方案

| 难点 | 解决方案 |
|------|---------|
| ESP32-P4 视频解码性能 | 使用预编译的 esp_extractor 库 + PPA 硬件加速 |
| 帧同步与画面撕裂 | DPI 面板 VSync 中断 + 信号量同步 |
| LCD 缓冲不足 | 双缓冲方案：优先使用面板原生帧缓冲，回退到 PSRAM 分配 |
| 多格式兼容 | 统一提取器注册中心，每种格式独立注册 |
| 播放结束检测 | 主检测：流结束标志；回退检测：5 次帧计数无变化判定 |
| SD 卡热插拔 | 启动时检测 SD 卡可用性，优雅降级到纯 UI 模式 |
| 交叉架构 | 为 6 种芯片架构预编译提取器库 |
