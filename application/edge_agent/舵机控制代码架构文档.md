# 舵机控制代码架构文档

## 1. 概述

舵机控制模块是 爱莉 系统中负责**物理舵机驱动与控制**的子系统，通过 MCPWM（Motor Control PWM）外设驱动两个舵机通道（0 和 1），提供角度设置、动作序列播放、缓动过渡等功能。

该模块由三个互补的代码层构成：

| 层次 | 文件 | 职责 |
|------|------|------|
| **Layer 1: MCPWM 硬件抽象层** | `servo_mcpwm.c` / `servo_mcpwm.h` | 封装 ESP-IDF MCPWM 外设驱动，提供 50Hz PWM 信号输出和角度→脉冲宽度转换 |
| **Layer 2: 动作序列播放器** | `motion.c` / `motion.h` | 动作序列的帧循环播放引擎，支持 FIXED / SWEEP / EASE 三种模式及多种缓动曲线 |
| **Layer 3: Capability 集成层** | `cap_servo.c` / `cap_servo.h` | 通过 爱莉 `claw_cap` 框架注册为 Capability Group，暴露三个可调用能力给 LLM 和 Event Router |

### 1.1 核心职责

- **Layer 1**: 初始化 MCPWM 定时器/操作器/比较器/发生器，将角度值转换为 50Hz PWM 脉冲宽度，驱动舵机 GPIO
- **Layer 2**: 按帧循环播放动作列表，每帧更新两个通道的角度，支持三种运动模式和 5 种缓动曲线，响应外部停止信号
- **Layer 3**: 懒初始化舵机硬件（首次调用时），管理运动播放任务的创建/停止/销毁，通过 JSON Schema 校验用户输入，返回执行结果

### 1.2 组件位置

```
components/claw_capabilities/cap_servo/
├── CMakeLists.txt               # 组件构建配置（依赖 json, esp_driver_mcpwm）
├── include/
│   ├── cap_servo.h              # 公开 API 头文件（注册函数 + 舵机句柄获取）
│   ├── servo_mcpwm.h            # MCPWM 硬件抽象层头文件
│   └── motion.h                 # 动作序列播放器头文件
├── skills/
│   └── cap_servo/
│       └── SKILL.md             # LLM Skill 文档
└── src/
    ├── cap_servo.c              # Capability 核心实现 (~300行)
    ├── servo_mcpwm.c            # MCPWM 硬件抽象层实现 (~120行)
    └── motion.c                 # 动作序列播放器实现 (~150行)
```

## 2. 架构层次

舵机控制模块采用**分层架构**，从底层到顶层依次为：

```
┌─────────────────────────────────────────────────┐
│                   Layer 3                        │
│              Capability 接口层                     │
│  (描述符定义 / 注册 / 懒初始化 / 任务管理)           │
│  set_servo_angle, play_motion_sequence, stop_servo│
├─────────────────────────────────────────────────┤
│                   Layer 2                        │
│           动作序列播放器 (Motion Player)            │
│  帧循环播放引擎 / 三种运动模式 / 5种缓动曲线         │
│  外部停止信号机制 / 单次/循环播放                    │
├─────────────────────────────────────────────────┤
│                   Layer 1                        │
│          MCPWM 硬件抽象层 (servo_mcpwm)            │
│  50Hz PWM 信号生成 / 角度→脉冲宽度转换              │
│  16位定时器 / 比较器匹配事件 / 发生器输出逻辑        │
└─────────────────────────────────────────────────┘
```

### 2.1 关键设计决策

#### 2.1.1 硬件抽象层独立于 Capability 框架

`servo_mcpwm` 是完全独立的底层模块，不依赖 `claw_cap` 或 爱莉 框架。它只提供三个纯函数：

```c
esp_err_t servo_mcpwm_init(servo_mcpwm_t *servo, int gpio_a, int gpio_b);
esp_err_t servo_mcpwm_set_angle(servo_mcpwm_t *servo, int channel, double degree);
esp_err_t servo_mcpwm_deinit(servo_mcpwm_t *servo);
```

这种设计使得 `servo_mcpwm` 层可以独立测试和复用（例如被 Lua 驱动模块或自定义组件直接调用），同时也允许 `cap_servo` 层的开发者只需关注 Capability 集成逻辑而不必处理 MCPWM 硬件细节。

#### 2.1.2 角度→脉冲宽度转换的配置化

`angle_to_ticks()` 函数采用三段参数化转换：

```
脉冲宽度 = 中点值 + (角度/最大角度) × 半范围值
```

| 配置宏 | 默认值 | 说明 |
|--------|--------|------|
| `CONFIG_APP_CLAW_SERVO_PULSE_MIN_US` | 405 | 最小脉冲宽度（对应 -max_angle） |
| `CONFIG_APP_CLAW_SERVO_PULSE_MAX_US` | 2595 | 最大脉冲宽度（对应 +max_angle） |
| `CONFIG_APP_CLAW_SERVO_MAX_ANGLE` | 135 | 最大机械角度 |

这些值可通过 `menuconfig` 配置，适用于 SG90 / MG996R 等常见舵机。转换结果被硬夹在 `[-max_angle, +max_angle]` 区间内。

#### 2.1.3 运动播放器作为独立引擎独立于 Capability

`motion_player_run_once()` 和 `motion_player_run_loop()` 是纯控制逻辑的函数，它们不接受 爱莉 框架的任何依赖，只依赖于 `servo_mcpwm_t` 句柄和 `motion_t` 数据表。

停止机制使用静态 `volatile bool` 标记 `s_stop_requested` 和 `s_running`，通过 `motion_player_stop()` / `motion_player_reset()` 控制，支持跨任务线程安全的中止操作。

#### 2.1.4 懒初始化 + 全局单例

`cap_servo` 维护一个全局静态的 `servo_mcpwm_t s_servo` 实例，通过 `ensure_servo()` 确保在第一次调用时才初始化 MCPWM 硬件。这种设计：

- 避免启动时不必要的舵机初始化（如果系统不需要舵机功能）
- 通过 `s_servo_initialized` 标记确保只初始化一次
- GPIO 号通过 Kconfig 配置（默认 CH0=GPIO4, CH1=GPIO5）

#### 2.1.5 motion 任务生命周期管理

`play_motion_sequence` 在独立的 FreeRTOS 任务中异步执行运动播放，`cap_servo.c` 负责管理该任务的生命周期：

- **创建**: `xTaskCreate(motion_task_fn, "motion_player", 4096, args, 5, &s_motion_task)`
- **停止**: `stop_motion_task()` 先发停止信号，等待最多 500ms，超时则 `vTaskDelete` 强制删除
- **互斥**: 新 motion 调用前自动停止旧序列；`set_servo_angle` 也会先停止 motion 任务

## 3. 各层详解

### 3.1 Layer 1 — MCPWM 硬件抽象层 (`servo_mcpwm`)

#### 3.1.1 数据结构

```c
typedef struct {
    mcpwm_timer_handle_t timer;        // MCPWM 定时器（50Hz）
    mcpwm_oper_handle_t oper;          // MCPWM 操作器
    mcpwm_cmpr_handle_t comparator[2]; // 比较器（每通道一个）
    mcpwm_gen_handle_t generator[2];   // 发生器（每通道一个）
    uint32_t period_ticks;             // 周期计数值（20000）
    int gpio[2];                       // GPIO 编号
} servo_mcpwm_t;
```

此结构体描述了 ESP-IDF MCPWM 外设的标准拓扑：

```
[MCPWM Timer] → [MCPWM Operator] → [Comparator 0] → [Generator 0] → GPIO_A
                                   → [Comparator 1] → [Generator 1] → GPIO_B
```

#### 3.1.2 初始化流程 (`servo_mcpwm_init`)

```
servo_mcpwm_init(servo, gpio_a, gpio_b):
  │
  ├─ 1. 创建 MCPWM 定时器
  │      timer_config:
  │        group_id = 0
  │        resolution_hz = 1,000,000 (1MHz)
  │        period_ticks = 20,000 (→ 50Hz)
  │        count_mode = UP
  │
  ├─ 2. 创建 MCPWM 操作器
  │      operator_config.group_id = 0
  │      connect: operator → timer
  │
  ├─ 3. 初始化 GPIO 数组
  │      gpio[0] = gpio_a, gpio[1] = gpio_b
  │
  ├─ 4. 对每个通道 (i=0,1):
  │      ├─ 创建比较器 (comparator_config, update_cmp_on_tez = 1)
  │      ├─ 创建发生器 (generator_config, gen_gpio_num = gpio[i])
  │      ├─ 设置定时器事件动作:
  │      │    当 timer UP 计数达到 EMPTY → output HIGH (周期开始置高)
  │      └─ 设置比较器事件动作:
  │           当 timer UP 计数达到 compare_value → output LOW (脉冲结束置低)
  │
  ├─ 5. 初始化角度: 设置 CH0=0°, CH1=0°
  │
  ├─ 6. 使能并启动定时器
  │
  └─ 7. 返回 (失败时调用 servo_mcpwm_deinit 清理已分配资源)
```

**PWM 时序图：**

```
Timer Count:  0 ────────── compare_value ──────────── 20000
                |              |                         |
Generator Out:  ────────────── ────                     ──
                HIGH           LOW                      HIGH
                |<-- 脉冲宽度 -->|
                舵机角度 = f(脉冲宽度)
```

#### 3.1.3 角度设置 (`servo_mcpwm_set_angle`)

```
servo_mcpwm_set_angle(servo, channel, degree):
  │
  ├─ 1. angle_to_ticks(degree) 计算脉冲宽度计数值
  │      ├─ 角度硬夹到 [-max_angle, +max_angle]
  │      ├─ 线性插值: pulse_us = center + (degree/max_angle) * half_range
  │      └─ 返回 (uint32_t)pulse_us (直接返回微秒数，与分辨率 1MHz 对应)
  │
  └─ 2. mcpwm_comparator_set_compare_value(comparator[channel], ticks)
```

#### 3.1.4 反初始化 (`servo_mcpwm_deinit`)

```
servo_mcpwm_deinit(servo):
  ├─ 停止并禁用定时器
  ├─ 删除发生器 (×2)
  ├─ 删除比较器 (×2)
  ├─ 删除操作器
  └─ 删除定时器
```

### 3.2 Layer 2 — 动作序列播放器 (`motion`)

#### 3.2.1 数据类型

```c
typedef enum {
    MOTION_FIXED,    // 固定角度保持
    MOTION_SWEEP,    // 往复扫摆
    MOTION_EASE,     // 缓动过渡到目标角度
} motion_mode_t;

typedef enum {
    EASE_LINEAR,         // 线性
    EASE_IN_QUAD,        // 缓入 (二次)
    EASE_OUT_QUAD,       // 缓出 (二次)
    EASE_IN_OUT_QUAD,    // 缓入缓出 (二次)
    EASE_IN_OUT_CUBIC,   // 缓入缓出 (三次) - 默认
} ease_type_t;

typedef struct {
    motion_mode_t mode;          // 运动模式
    double angle;                // 目标角度 (FIXED/EASE)
    double min_angle;            // 最小角度 (SWEEP 范围下限)
    double max_angle;            // 最大角度 (SWEEP 范围上限)
    double step;                 // SWEEP 步进量
    uint32_t step_delay_ms;      // SWEEP 每步延时
    ease_type_t ease_type;       // EASE 缓动曲线类型
} servo_action_t;

typedef struct {
    uint8_t id;                  // 动作序号 (1-based)
    uint32_t duration_ms;        // 动作持续时间
    servo_action_t servo[2];     // 两个通道的动作配置
} motion_t;
```

#### 3.2.2 三种运动模式

| 模式 | 用途 | 行为 |
|------|------|------|
| `MOTION_FIXED` | 固定角度定位 | 立即设置到 `angle`，在整个 `duration_ms` 内保持不变 |
| `MOTION_SWEEP` | 往复扫摆（如舵机摇头） | 从 `min_angle` 到 `max_angle` 按 `step` 步进往复，每步间隔 `step_delay_ms` |
| `MOTION_EASE` | 平滑过渡 | 从当前角度缓动到 `angle`，缓动曲线由 `ease_type` 指定，持续 `duration_ms` |

#### 3.2.3 缓动曲线 (`apply_ease`)

所有曲线的输入 `t ∈ [0, 1]`，输出为 `[0, 1]` 范围内插值后的比例因子：

| 曲线 | 公式 | 效果 |
|------|------|------|
| `EASE_LINEAR` | `t` | 匀速运动 |
| `EASE_IN_QUAD` | `t²` | 先慢后快 |
| `EASE_OUT_QUAD` | `t(2-t)` | 先快后慢 |
| `EASE_IN_OUT_QUAD` | `t<0.5 ? 2t² : -1+(4-2t)t` | 两头慢中间快 |
| `EASE_IN_OUT_CUBIC` | `t<0.5 ? 4t³ : 1-(2-2t)³/2` | 更平滑的缓入缓出（默认） |

#### 3.2.4 帧循环引擎 (`motion_player_run_internal`)

```
motion_player_run_internal(servo, table, count, loop)
  │
  ├─ 初始化: sweep_angle[2]={0}, sweep_dir[2]={1}, current[2]={0}
  ├─ s_running = true
  │
  ├─ for idx = 0; !s_stop_requested; idx++:
  │   ├─ if idx >= count:
  │   │   ├─ if loop → idx = 0 (重置为第一帧)
  │   │   └─ else → break (播放完毕)
  │   │
  │   ├─ 当前帧: m = &table[idx]
  │   ├─ 记录开始时间: start = xTaskGetTickCount()
  │   │
  │   ├─ 预计算:
  │   │   ├─ SWEEP 模式: 重置 sweep_dir[ch] = 1
  │   │   └─ EASE 模式: 记录 ease_start[ch] = current[ch]
  │   │
  │   ├─ 帧循环: while !s_stop_requested && elapsed_ms < duration_ms:
  │   │   ├─ 对每个通道 (ch=0,1):
  │   │   │   ├─ FIXED:  target = a->angle (保持不变)
  │   │   │   ├─ SWEEP:  target += dir * step
  │   │   │   │   ├─ 超出 max → 回弹 dir=-1
  │   │   │   │   └─ 超出 min → 回弹 dir=+1
  │   │   │   └─ EASE:   t = elapsed/duration
  │   │   │              target = ease_start + (angle - ease_start) * eased(t)
  │   │   ├─ servo_mcpwm_set_angle(servo, ch, target)
  │   │   ├─ 更新 current[ch] = target
  │   │   │
  │   │   └─ 计算帧间隔:
  │   │       ├─ 默认 20ms (50Hz)
  │   │       └─ SWEEP 模式: 取最小 step_delay_ms
  │   │
  │   ├─ 帧结束: EASE 模式确保最终角度精确等于 a->angle
  │   └─ idx++ 进入下一帧
  │
  ├─ s_running = false
  └─ 返回
```

**帧间隔策略：**
- 默认 20ms（50Hz 刷新率）
- 当任一通道为 SWEEP 模式时，帧间隔取所有通道 `step_delay_ms` 中的最小值（通常小于 20ms，如 14ms）

#### 3.2.5 停止机制

```
motion_player_stop()     → s_stop_requested = true  (跨任务信号)
motion_player_reset()    → s_stop_requested = false, s_running = false
motion_player_is_running() → 返回 s_running 状态
```

停止信号使用 `volatile` 关键字确保跨 FreeRTOS 任务间的可见性。帧循环引擎在每次循环开始时检查 `s_stop_requested`，在每帧结束后检查 `s_stop_requested`，确保快速响应。

#### 3.2.6 单次 vs 循环

| 函数 | 实现 | 行为 |
|------|------|------|
| `motion_player_run_once(servo, table, count)` | 调用 `_internal(servo, table, count, false)` | 播放完所有动作后返回 |
| `motion_player_run_loop(servo, table, count)` | 调用 `_internal(servo, table, count, true)` | 索引到末尾后重置为 0，无限循环直到被停止 |

### 3.3 Layer 3 — Capability 集成层 (`cap_servo`)

#### 3.3.1 全局状态

```c
static servo_mcpwm_t s_servo = {0};            // 全局舵机实例
static bool s_servo_initialized = false;        // 初始化标记
static TaskHandle_t s_motion_task = NULL;       // 运动播放任务句柄
```

**Kconfig 默认值：**
```c
#ifndef CONFIG_APP_CLAW_SERVO_GPIO_A
#define CONFIG_APP_CLAW_SERVO_GPIO_A 4     // 通道0 GPIO
#endif
#ifndef CONFIG_APP_CLAW_SERVO_GPIO_B
#define CONFIG_APP_CLAW_SERVO_GPIO_B 5     // 通道1 GPIO
#endif
```

#### 3.3.2 懒初始化 (`ensure_servo`)

```c
static esp_err_t ensure_servo(void)
{
    if (s_servo_initialized) {
        return ESP_OK;                   // 已经初始化，直接返回
    }
    // 首次调用时初始化 MCPWM 硬件
    esp_err_t ret = servo_mcpwm_init(&s_servo,
                                     CONFIG_APP_CLAW_SERVO_GPIO_A,
                                     CONFIG_APP_CLAW_SERVO_GPIO_B);
    if (ret == ESP_OK) {
        s_servo_initialized = true;
    }
    return ret;
}
```

#### 3.3.3 舵机缓动归零 (`servo_ease_to`)

`cap_servo.c` 内置了 `set_servo_angle` 专用的缓动函数 `servo_ease_to`，与 Motion Player 的 EASE 模式不同点在于：

- 直接在当前任务上下文中阻塞执行（vs Motion Player 在独立任务中异步执行）
- 使用固定的 cubic ease-in-out 曲线 (`3t² - 2t³`)
- 帧间隔固定为 20ms
- 从 0° 开始（因为不跟踪上次设置的角度）

```c
static void servo_ease_to(servo_mcpwm_t *servo, int channel,
                          double target, uint32_t duration_ms)
{
    if (duration_ms == 0) {                         // 立即到位
        servo_mcpwm_set_angle(servo, channel, target);
        return;
    }
    // 50Hz 插值，共 steps = duration_ms / 20 步
    for (uint32_t i = 1; i <= steps; i++) {
        double t = (double)i / steps;
        double eased = t * t * (3.0 - 2.0 * t);     // cubic ease-in-out
        double angle = current + delta * eased;
        servo_mcpwm_set_angle(servo, channel, angle);
        vTaskDelay(pdMS_TO_TICKS(20));
    }
    servo_mcpwm_set_angle(servo, channel, target);  // 确保精确到达
}
```

#### 3.3.4 Motion 任务管理 (`stop_motion_task` / `motion_task_fn`)

**停止逻辑：**
```c
static void stop_motion_task(void)
{
    if (s_motion_task) {
        motion_player_stop();                    // 发停止信号
        // 最多等待 500ms 让任务自行退出
        while (motion_player_is_running() &&
               (xTaskGetTickCount() - start) < pdMS_TO_TICKS(500)) {
            vTaskDelay(pdMS_TO_TICKS(10));
        }
        if (eTaskGetState(s_motion_task) != eDeleted) {
            vTaskDelete(s_motion_task);          // 强制删除
        }
        s_motion_task = NULL;
    }
    motion_player_reset();                       // 复位停止标记
}
```

**任务函数：**
```c
static void motion_task_fn(void *arg)
{
    motion_task_args_t *args = (motion_task_args_t *)arg;
    if (args->loop) {
        motion_player_run_loop(args->servo, args->table, args->count);
    } else {
        motion_player_run_once(args->servo, args->table, args->count);
    }
    free(args->table);    // 释放 motion_t 数组
    free(args);           // 释放参数结构体
    s_motion_task = NULL;
    vTaskDelete(NULL);
}
```

#### 3.3.5 三个 Capability 能力

#### 3.3.5.1 `set_servo_angle`

| 属性 | 值 |
|------|------|
| ID | `set_servo_angle` |
| Family | `servo` |
| Kind | `CALLABLE` |
| Flags | `CALLABLE_BY_LLM` |
| 阻塞/非阻塞 | **阻塞**（在当前任务中执行缓动） |

**参数（JSON Schema）：**
```json
{
  "type": "object",
  "properties": {
    "channel": {"type": "integer", "enum": [0, 1]},
    "angle": {"type": "number"},
    "duration_ms": {"type": "integer"}
  },
  "required": ["channel", "angle"]
}
```

**执行流程：**
```
cap_servo_set_angle_execute(input_json):
  ├─ 1. 解析 JSON → channel, angle, duration_ms(默认1000)
  ├─ 2. 校验 channel ∈ {0,1}
  ├─ 3. ensure_servo() → 懒初始化
  ├─ 4. stop_motion_task() → 停止正在播放的 motion
  ├─ 5. servo_ease_to(&s_servo, channel, angle, duration_ms)
  └─ 6. 返回 "Servo <ch> set to <angle>°"
```

#### 3.3.5.2 `play_motion_sequence`

| 属性 | 值 |
|------|------|
| ID | `play_motion_sequence` |
| Family | `servo` |
| Kind | `CALLABLE` |
| Flags | `CALLABLE_BY_LLM` |
| 阻塞/非阻塞 | **非阻塞**（在独立 FreeRTOS 任务中异步执行） |

**参数（JSON Schema，精简）：**
```json
{
  "type": "object",
  "properties": {
    "actions": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "duration_ms": {"type": "integer"},
          "servo0": {"$ref": "#/definitions/servo_config"},
          "servo1": {"$ref": "#/definitions/servo_config"}
        }
      }
    },
    "loop": {"type": "boolean"}
  },
  "required": ["actions"]
}
```

**执行流程：**
```
cap_servo_play_motion_execute(input_json):
  ├─ 1. 解析 JSON
  │     ├─ actions: 动作数组 (1-32项)
  │     ├─ loop: 是否循环 (默认false)
  │     └─ 每个 action 解析:
  │         ├─ duration_ms: 动作持续时间
  │         ├─ servo0/servo1.mode: fixed/sweep/ease
  │         ├─ servo0/servo1.angle: 目标角度
  │         ├─ servo0/servo1.min_angle / max_angle: sweep 范围
  │         ├─ servo0/servo1.step: sweep 步进
  │         ├─ servo0/servo1.step_delay_ms: sweep 步进延时
  │         └─ servo0/servo1.ease_type: 缓动曲线
  │
  ├─ 2. 校验: 1 ≤ actions ≤ 32
  ├─ 3. calloc 分配 motion_t 数组
  ├─ 4. 填充 motion_t 结构体
  ├─ 5. ensure_servo() → 懒初始化
  ├─ 6. stop_motion_task() → 停止旧 motion
  ├─ 7. 创建 motion_task_args_t 参数
  ├─ 8. xTaskCreate(motion_task_fn, "motion_player", 4096, args, 5, &s_motion_task)
  └─ 9. 返回 "Playing N motion(s)" 或 "in loop"
```

## 7. 角度脉冲宽度转换算法

角度到脉冲宽度的转换采用**线性插值**算法（`angle_to_ticks`）：

```
参数:
  min_pulse  = CONFIG_APP_CLAW_SERVO_PULSE_MIN_US   (默认 405μs)
  max_pulse  = CONFIG_APP_CLAW_SERVO_PULSE_MAX_US   (默认 2595μs)
  max_angle  = CONFIG_APP_CLAW_SERVO_MAX_ANGLE      (默认 135°)

计算:
  center    = (min_pulse + max_pulse) / 2
  range     = (max_pulse - min_pulse) / 2
  pulse_us  = center + (degree / max_angle) × range

  返回值: (uint32_t)pulse_us
```

| 角度 | 脉冲宽度 | 说明 |
|------|----------|------|
| -135° | 405 μs | 最小脉冲 |
| 0° | 1500 μs | 中位脉冲 |
| +135° | 2595 μs | 最大脉冲 |

由于 MCPWM 定时器配置为 `resolution_hz = 1,000,000`，每秒计数 1,000,000 次。每个计数值对应 1μs，所以 `pulse_us` 可直接作为比较器的 compare_value 使用。

**角度钳位：** 所有输入角度在被传递到此函数之前，或在此函数内部，被限制在 `[-max_angle, +max_angle]` 范围：
- `servo_mcpwm_set_angle` 内部调用 `angle_to_ticks` 时自动钳位
- `cap_servo.c` 的 `clamp_angle()` 函数在缓动前预先钳位

## 12. 性能与安全考虑

### 12.1 时序性能

| 操作 | 时间 | 说明 |
|------|------|------|
| `servo_mcpwm_set_angle` | ≈ 5μs | 仅一次 MCPWM API 调用 |
| `angle_to_ticks` | < 1μs | 纯浮点计算 |
| `servo_ease_to` 单步 | 20ms + 角度计算 | 主要是 `vTaskDelay(20ms)` |
| Motion Player 单帧 | 14-20ms | 依 SWEEP step_delay_ms 而定 |
| `stop_motion_task` 最大等待 | 500ms | 等待 motion 播放任务退出 |

### 12.2 内存使用

| 分配 | 大小 | 位置 |
|------|------|------|
| `servo_mcpwm_t` 静态 | ~40 bytes | BSS |
| `motion_t[count]` 动态 | `count × 72 bytes` (最大 32 × 72 = 2.3KB) | Heap |
| `motion_task_args_t` | ~16 bytes | Heap |
| Motion Player 任务栈 | 4KB | Heap |

### 12.3 安全设计

| 方面 | 策略 |
|------|------|
| 角度硬钳位 | 所有角度在设置前钳位到 `[-max_angle, +max_angle]` |
| 通道校验 | channel 必须为 0 或 1 |
| motion 数量限制 | actions 长度限制为 1-32 |
| motion 任务互斥 | 新 motion 调用前自动停止旧序列 |
| 重复注册防护 | `cap_servo_register_group` 检查 `claw_cap_group_exists` |
| 任务安全退出 | `s_stop_requested` volatile 标记 + 超时强制删除 |
| JSON Schema | 输入参数通过 `input_schema_json` 描述，框架可提前校验 |
| 阻塞式 `set_servo_angle` 安全 | 在当前任务同步执行，不支持中断 |

## 13. 局限性与改进建议

### 13.1 当前架构的局限性

1. **不跟踪上次角度**：`servo_ease_to` 从 0° 假设开始缓动，未保存每个通道的当前角度。当连续调用 `set_servo_angle` 时，缓动起始点可能不准确
2. **阻塞式 `set_servo_angle`**：缓动过程在调用者上下文同步执行，长时间（如 5 秒）缓动会阻塞其他 LLM 工具调用
3. **无 Graceful 停止**：Motion 任务停止时使用 `vTaskDelete` 强制删除（超时后），未提供优雅排空当前帧的方式
4. **无并发保护**：未使用互斥锁保护全局状态 `s_servo` 的并发访问（当前通过单一任务调用确保安全）
5. **无电源管理**：舵机在空闲状态时 MCPWM 信号依然持续输出（保持当前角度），没有进入低功耗模式

### 13.2 改进建议

1. **角度追踪**：在 `cap_servo.c` 中增加 `double s_last_angle[2]` 记录每个通道的上次角度，`servo_ease_to` 以此作为缓动起始点
2. **异步 `set_servo_angle`**：将 `set_servo_angle` 改为异步执行，通过队列投递到 motion 任务（与 `play_motion_sequence` 合并处理路径）
3. **Graceful 停止**：在 motion 帧循环中增加"完成当前帧后退出"的逻辑，代替强制删除
4. **互斥保护**：为 `s_servo` 增加互斥锁，支持多任务并发调用（虽然当前场景无此需求）
5. **角度查询**：增加 `servo_mcpwm_get_angle` 查询当前角度（从比较器读回），用于状态上报
6. **节能模式**：空闲时调用 `mcpwm_timer_start_stop(STOP_EMPTY)` 停止 PWM 输出，需要时重新启动

## 14. 总结

舵机控制模块由三层独立但紧密协作的代码组成，每层只关注自己的责任边界：

### Layer 1: servo_mcpwm（硬件抽象层）
- 封装 MCPWM 外设的完整生命周期（初始化 → 角度设置 → 反初始化）
- 使用 1MHz 分辨率 50Hz 的 PWM 信号驱动标准舵机
- 通过线性插值将角度值映射为脉冲宽度
- 所有参数（脉冲范围、最大角度）均可通过 Kconfig 配置

### Layer 2: motion（动作序列播放器）
- 纯控制逻辑引擎，不依赖 爱莉 框架
- 支持三种运动模式（固定/扫摆/缓动）和五种缓动曲线
- 帧循环引擎默认 50Hz 刷新率，SWEEP 模式下自动调整帧间隔
- 通过 volatile 停止信号实现跨任务安全中止

### Layer 3: cap_servo（Capability 集成层）
- 通过 `claw_cap` 框架注册三个 LLM 可用能力
- 懒初始化策略，按需创建硬件资源
- 运动播放作为独立 FreeRTOS 任务异步执行
- 提供 JSON Schema 校验、角度钳位、任务互斥管理

整体设计遵循以下原则：
- **分层解耦**：硬件驱动、控制逻辑、框架集成各层独立，可分别测试/复用
- **组件化**：独立的目录、构建配置、头文件/实现分离
- **框架集成**：通过 `claw_cap_descriptor_t` 和 `claw_cap_group_t` 注册到核心系统
- **异步播放**：`play_motion_sequence` 通过独立 FreeRTOS 任务异步执行，不阻塞调用者
- **安全优先**：角度硬钳位、通道校验、数量限制、任务互斥、超时保护
- **Skill 配套**：提供 LLM 使用的 Skill 文档，遵循渐进式披露原则
