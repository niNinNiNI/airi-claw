# ESP32-P4 硬件显示架构

## 整体概览

本项目的显示系统基于 **ESP-IDF LCD 框架** 和 **ESP Board Manager** 构建，采用分层架构实现硬件抽象、所有权仲裁和多种显示接口（MIPI DSI、SPI、RGB）的支持。显示内容由 **表情动画引擎（emote）**、**情绪视频系统（emotion_video）**、**视频播放器（video_player）** 和 **Lua 脚本** 四个消费者通过仲裁器协调共享。

## 一、硬件描述层（Board YAML）

每个开发板通过 YAML 文件声明硬件配置，由 `esp_board_manager` 解析并初始化。

### 文件结构（以 P4 WiFi6 Touch LCD 4.3" 为例）

```
boards/espressif/esp32_p4_wifi6_touch_lcd_4_3/
├── board_info.yaml              # 板卡元信息（芯片、制造商）
├── board_peripherals.yaml       # 物理外设声明（I2C、DSI、LEDC、LDO）
├── board_devices.yaml           # 逻辑设备声明（LCD、触摸、音频、SD卡）
├── setup_device.c               # 板级工厂函数（面板初始化命令）
└── sdkconfig.defaults.board     # 板级默认 Kconfig
```

### board_peripherals.yaml — 物理外设

定义芯片引脚的物理外设，包括：

| 外设 | 说明 | 示例配置（P4 WiFi6 Touch LCD） |
|------|------|-------------------------------|
| `i2c_master` | I2C 总线 | SDA=7, SCL=8, 用于触摸和音频 |
| `dsi_display` | MIPI DSI 总线 | 2 data lanes, 500 Mbps |
| `ledc_backlight` | LEDC PWM 背光 | GPIO26, 4 kHz, 13-bit, 反相输出 |
| `ldo_mipi` | LDO 供电 | VO3, 2.5V, 为 MIPI 供电 |
| `i2s_audio_out/in` | I2S 音频 | 全双工 48 kHz, MCLK=13 |

### board_devices.yaml — 逻辑设备

将物理外设组合为逻辑设备：

- **display_lcd**：芯片 `st7701`，子类型 `dsi`，480×800，RGB565，双帧缓冲 + DMA2D，30 MHz DPI 时钟
- **lcd_touch**：芯片 `gt911`，I2C 地址 0x5D/0x14，最大坐标 480×800，镜像XY
- **lcd_brightness**：LEDC 背光控制，默认 100% 亮度

## 二、Board Manager 设备驱动层

`esp_board_manager` 是核心中间件，负责：

1. 解析 YAML 配置
2. 按依赖顺序初始化物理外设（LDO → DSI → 面板 → 背光）
3. 调用板级工厂函数创建面板和触摸句柄
4. 对外提供统一的设备句柄查询接口

## 五、显示所有权仲裁层（display_arbiter）

> **核心问题**：系统中有多个渲染源（emote、emotion_video、video_player、Lua 绘图），但 LCD 面板只有一个 `panel_handle`。display_arbiter 通过所有权机制确保同一时刻只有一个渲染源可以写入 LCD。

由于显示面板只有一个，多个消费者（emote、emotion_video、Lua、video_player）需要通过仲裁机制互斥访问。

**文件位置**：
- 头文件：[display_arbiter.h](../../../../components/common/display_arbiter/include/display_arbiter.h)
- 实现：[display_arbiter.c](../../../../components/common/display_arbiter/display_arbiter.c)

### 5.1 所有权类型

```c
typedef enum {
    DISPLAY_ARBITER_OWNER_NONE = 0,  // 无所有者
    DISPLAY_ARBITER_OWNER_LUA,       // Lua 脚本（绝对优先）
    DISPLAY_ARBITER_OWNER_EMOTE,     // 表情动画
    DISPLAY_ARBITER_OWNER_VIDEO,     // 视频播放（默认启动所有者）
} display_arbiter_owner_t;
```

所有权优先级：**Lua > Emote/Video**。Lua 具有绝对优先权，可抢占任何其他所有者。

### 5.2 内部状态结构

```c
typedef struct {
    SemaphoreHandle_t lock;           // 互斥锁（1s 超时）
    display_arbiter_owner_t owner;    // 当前所有者
    uint32_t lua_depth;               // Lua 嵌套深度（支持嵌套 acquire）
    display_arbiter_owner_changed_cb_t callback;  // 所有者变更回调
    void *callback_user_ctx;
} display_arbiter_state_t;

static display_arbiter_state_t s_state = {
    .owner = DISPLAY_ARBITER_OWNER_VIDEO,  // 默认：视频拥有显示权
};
```

### 5.3 acquire 逻辑（获取显示权）

```
display_arbiter_acquire(owner)
  │
  ├── 获取互斥锁
  │
  ├── owner == LUA:
  │     ├── lua_depth++
  │     └── 如果当前 owner != LUA → 切换到 LUA，通知回调
  │
  └── owner == VIDEO:
        ├── 如果 lua_depth > 0 → 拒绝（返回 ESP_ERR_INVALID_STATE）
        └── 如果当前 owner != VIDEO → 切换到 VIDEO，通知回调
```

### 5.4 release 逻辑（释放显示权）

```
display_arbiter_release(owner)
  │
  ├── 获取互斥锁
  │
  ├── owner == LUA:
  │     ├── lua_depth--
  │     └── 如果 lua_depth == 0 且当前 owner == LUA → 切换到 NONE，通知回调
  │
  └── owner == VIDEO:
        └── 如果当前 owner == VIDEO → 切换到 NONE，通知回调
```

### 5.5 所有权状态机

```
                    ┌──────────────────────────┐
                    │                          │
                    ▼                          │
              ┌──────────┐                    │
         ┌───→│   NONE   │←──────────┐        │
         │    └────┬─────┘           │        │
         │         │                 │        │
         │   video_acquire      video_release  │
         │         │                 │        │
         │         ▼                 │        │
         │  ┌────────────┐          │        │
         │  │   VIDEO    │──────────┘        │
         │  │ (默认启动)  │                   │
         │  └─────┬──────┘                   │
         │        │                          │
         │        │ lua_acquire              │
         │        │ (lua_depth: 0→1)         │
         │        ▼                          │
         │  ┌────────────┐                   │
         │  │    LUA     │←── lua_acquire    │
         │  │ (绝对优先)  │    (lua_depth 增加)│
         │  └─────┬──────┘                   │
         │        │                          │
         │        │ lua_release              │
         │        │ (lua_depth 减到 0)        │
         │        │                          │
         └────────┘                          │
                                             │
         video_task 每 500ms 轮询重获取 ──────┘
```

### 5.6 关键设计细节

1. **Lua 嵌套支持**：`lua_depth` 计数器允许多个 Lua 脚本嵌套获取显示权。只有当最外层 release 时（`lua_depth == 0`），所有权才真正变为 NONE。

2. **Lua 绝对优先**：当 `lua_depth > 0` 时，Video 的 acquire 调用直接返回 `ESP_ERR_INVALID_STATE`。这意味着 Lua 脚本在执行期间对屏幕有独占控制权。

3. **默认 owner = VIDEO**：系统启动时 `s_state.owner = DISPLAY_ARBITER_OWNER_VIDEO`，视频播放器拥有显示权。当 Video 释放后，owner 变为 NONE，video_task 通过轮询重新获取。

4. **所有者变更回调**：当 owner 发生变化时，注册的回调函数被调用。Emote 用此机制在恢复控制权时刷新画面。

5. **无锁读取**：`get_owner` 和 `is_owner` 无锁读取（`s_state.owner` 是 enum，单次内存访问是原子的）。

6. **运行时清理保证**：Lua 脚本异常退出或强制停止时，`lua_display_runtime_cleanup()` 无条件调用 `display_arbiter_release(LUA)`，确保 video_task 可以恢复播放。

### 5.7 屏幕切换场景

#### 场景一：视频文件切换（同所有者内操作）

情绪切换是**同所有者（VIDEO）内的操作**，不需要重新 acquire。video_task 收到 SWITCH_FILE 命令后，先停止旧文件再启动新文件，整个过程保持 VIDEO 所有权不释放。这避免了切换瞬间被其他所有者抢占的竞态窗口。

#### 场景二：Lua 脚本接管屏幕

```
Lua 执行 display.init()
  → display_arbiter_acquire(LUA) → lua_depth: 0→1 → owner: VIDEO→LUA

video_task 播放循环:
  每 50ms 检测到 display_arbiter_is_owner(VIDEO) == false
    → stop_current_playback()
    → 进入重获取循环（每 500ms 重试）

Lua 执行完毕:
  display.deinit() → display_arbiter_release(LUA) → lua_depth: 1→0 → owner: LUA→NONE

video_task 重获取:
  display_arbiter_acquire(VIDEO) → 成功 → 恢复播放之前被中断的视频
  如果在等待期间收到新的 SWITCH_FILE，会更新播放目标
```

**屏幕结果**：Lua 脚本期间显示 Lua 绘制内容；脚本结束后自动恢复视频播放（最多 500ms 延迟）。

#### 场景三：LLM 调用 lua_stop_all_jobs 强制停止

```
LLM 调用 lua_stop_all_jobs(exclusive="display")
  → cap_lua_async_stop_all_jobs("display")
    → 设置 stop_requested = true
    → 等待 Lua 任务终止
    → cap_lua_run_runtime_cleanups()
      → lua_display_runtime_cleanup()
        → display_arbiter_release(LUA) → owner: NONE

video_task 重获取:
  display_arbiter_acquire(VIDEO) → 成功 → 恢复播放
```

**屏幕结果**：Lua 被强制停止后，屏幕自动恢复视频播放。

### 5.8 线程安全模型

#### 涉及的任务与优先级

| 任务 | 优先级 | 角色 |
|------|--------|------|
| `video_task` | 6 | 视频命令消费者，串行执行所有播放操作 |
| extract_task（stream adapter 内部） | 5 | MJPEG 解封装 + JPEG 硬件解码 |
| `vid_touch` | 4 | 触摸轮询（按钮交互） |
| HTTP server tasks | 5 | 处理 API 请求 |
| LLM agent tasks | 可变 | 执行 claw_cap call |

#### 保护机制

| 资源 | 保护方式 | 说明 |
|------|----------|------|
| `display_arbiter.owner` | FreeRTOS Mutex（1s 超时） | acquire/release 串行化 |
| 视频切换请求 | FreeRTOS Queue（4 槽位） | 多生产者 → 单消费者（video_task） |
| 帧缓冲区 | 无竞态 | extract_task 写入，video_task 串行控制生命周期 |
| stream adapter | 内部 event group | set_file 内部先 stop 再 set，stop 等待 extract_task 确认 |
| `display_arbiter.lua_depth` | 同一把 Mutex | 与 owner 一起受保护 |

**锁策略**：`acquire` 和 `release` 均在互斥锁保护下执行；回调通知在**释放锁之后**执行，避免死锁。

### 5.9 公共 API

| 函数 | 说明 |
|------|------|
| `display_arbiter_acquire(owner)` | 请求显示所有权，Lua 优先，失败时返回 `ESP_ERR_INVALID_STATE` |
| `display_arbiter_release(owner)` | 释放显示所有权 |
| `display_arbiter_get_owner()` | 查询当前所有权（无锁读取） |
| `display_arbiter_is_owner(owner)` | 检查是否为指定所有者（无锁读取） |
| `display_arbiter_set_owner_changed_callback(cb, ctx)` | 注册所有权变更回调 |

## 六、显示硬件抽象层（display_hal）

`display_hal` 封装了 LCD 面板句柄，提供设备无关的绘图接口。它被 Lua display 模块直接调用。

### 核心能力

| 类别 | 功能 |
|------|------|
| **生命周期** | `create` / `destroy` |
| **帧控制** | `begin_frame` / `end_frame` / `present` / `present_rect` |
| **几何** | `width` / `height` |
| **绘图** | 像素、直线、矩形（填充/描边）、圆（填充/描边）、椭圆（填充/描边）、圆弧（填充/描边）、三角形（填充/描边）、圆角矩形（填充/描边） |
| **文字** | bitmap 字体渲染（通过 `esp_painter`），支持左/中/右对齐和上/中/下垂直对齐 |
| **位图** | RGB565 位图绘制、裁剪、缩放 |
| **JPEG** | ROM 内置 TJpgDec 解码，支持裁剪、缩放和尺寸查询 |
| **背光** | `set_backlight` 开关控制 |
| **剪裁** | `set_clip_rect` / `clear_clip_rect` |
| **动画信息** | `get_animation_info` 查询帧缓冲状态 |

### 支持的三种面板接口

```c
typedef enum {
    DISPLAY_HAL_PANEL_IF_IO,       // SPI / 并口（通过 esp_lcd_panel_io）
    DISPLAY_HAL_PANEL_IF_RGB,      // RGB 接口（通过 esp_lcd_panel_rgb）
    DISPLAY_HAL_PANEL_IF_MIPI_DSI, // MIPI DSI 接口
} display_hal_panel_if_t;
```

### 双缓冲机制

- 帧缓冲分配在 **PSRAM** 中（`MALLOC_CAP_SPIRAM`）
- 最多支持 2 个帧缓冲（自动检测 PSRAM 可用量）
- `begin_frame` 时从 visible buffer 复制到 draw buffer（非 clear 模式）
- `present` 时提交 draw buffer 到面板并交换缓冲
- SPI/并口面板自动进行 RGB565 字节序交换（`__builtin_bswap16`）
- DSI 接口使用 DPI 面板事件回调，RGB 接口使用 RGB 面板事件回调

## 七、应用层消费者

### 7.1 Emote（表情动画引擎）

`emote` 是传统的表情动画引擎，基于 `esp_emote_gfx`（内部使用 LVGL v9）渲染。

**初始化流程：**

```
app_claw_ui_start()
  → emote_start()
      → emote_load_board_display()
          → esp_board_manager_get_device_handle("display_lcd")  // 获取面板句柄
          → esp_board_manager_get_device_config("display_lcd")  // 获取面板配置
      → emote_get_default_config()    // 构建配置（分辨率、双缓冲、FPS=10）
      → display_arbiter_set_owner_changed_callback()  // 注册所有权变更回调
      → emote_init()                  // 创建 emote 实例
      → emote_mount_and_load_assets() // 从 "emote" 分区加载动画资源
      → emote_set_network_status()    // 设置初始状态（offline）
```

**核心机制：**

- **flush 回调**：直接调用 `esp_lcd_panel_draw_bitmap()` 将渲染结果写入面板
- **所有权检查**：每次 flush 前通过 `display_arbiter_is_owner(EMOTE)` 确认是否仍有控制权
- **所有者变更回调**：当其他消费者释放控制权且所有权变更为 EMOTE 时，自动调用 `emote_notify_all_refresh()` 刷新画面
- **颜色字节序**：SPI 面板自动进行字节交换（`swap = true`），DSI/RGB 面板不交换
- **网络状态联动**：Wi-Fi 连接/断开时切换表情（"swim" / "offline"）
- **资源配置**：支持从分区加载（`EMOTE_SOURCE_PARTITION`），enable mmap 加速（非 XIP_PSRAM 模式）

### 7.2 Emotion Video（情绪视频系统）

`emotion_video` 是新的情绪表达系统，通过 `video_player` 循环播放 SD 卡上的 MP4 视频文件来展示不同的情绪状态。

**组件位置：** `application/edge_agent/components/emotion_video/`

**10 种情绪视频：**

| 枚举值 | 文件名 | 说明 |
|--------|--------|------|
| `M01_IDLE_SHAKE` | m01_idle_shake.mp4 | 空闲晃动 |
| `M02_SWAY` | m02_sway.mp4 | 摇摆 |
| `M03_CALM` | m03_calm.mp4 | 平静 |
| `M04_WAVE` | m04_wave.mp4 | 挥手 |
| `M05_TIRED` | m05_tired.mp4 | 疲倦 |
| `M06_SLIGHT_SWAY` | m06_slight_sway.mp4 | 轻微摇摆 |
| `M07_BREATHING` | m07_breathing.mp4 | 呼吸 |
| `M08_HAND_MOVES` | m08_hand_moves.mp4 | 手动 |
| `M09_NOD` | m09_nod.mp4 | 点头 |
| `M10_RELAXED` | m10_relaxed.mp4 | 放松 |

**API：**

| 函数 | 说明 |
|------|------|
| `emotion_video_set(emotion)` | 切换到指定情绪视频（循环播放） |
| `emotion_video_get_current()` | 获取当前播放的情绪 |
| `emotion_video_stop()` | 停止播放并释放显示 |
| `emotion_video_get_name(emotion)` | 枚举值 → 名称字符串 |
| `emotion_video_from_name(name)` | 名称字符串 → 枚举值 |

**实现机制：**
- 视频文件存储在 SD 卡 `/sdcard/videos/` 目录
- 通过 `video_player_play_file(path, true)` 循环播放单个视频
- 通过 `video_player_play_playlist(paths, count, loop)` 顺序播放多个视频并支持列表循环
- 当前情绪状态由 FreeRTOS 互斥锁保护
- 启动时 `app_main()` 最后调用 `emotion_video_start_default_cycle()` 开始默认循环：m01 → m02 → m03 → m01...

### 7.3 Capability 和 Lua 绑定

`emotion_video` 通过以下方式暴露给 AI 和脚本：

**cap_emotion**（LLM 可调用能力）：
- `set_emotion`：LLM 通过 JSON 调用切换情绪（如 `{"emotion": "m04_wave"}`）
- `get_emotion`：查询当前情绪名称

**lua_module_emotion**（Lua 脚本绑定）：
- `emotion.set(name)`：Lua 脚本切换情绪
- `emotion.get()`：Lua 脚本查询当前情绪

### 7.4 Video Player（视频播放器）

- 从 SD 卡读取 MP4/AVI 文件
- 使用 `display_arbiter` 获取显示所有权
- 通过 `esp_lcd_panel_draw_bitmap()` 逐帧输出
- 帧缓冲分配在 PSRAM（480×800×2 RGB565）
- 集成 `esp_codec_dev` 音频播放
- 在 `app_main()` 中通过 `video_player_init()` 提前初始化

### 7.5 Lua 模块

| 模块 | 功能 | 依赖 |
|------|------|------|
| `lua_module_display` | 绘图 API（通过 display_hal） | display_hal, display_arbiter |
| `lua_module_lcd` | 原始 LCD 面板控制（SPI/QSPI） | esp_lcd_panel |
| `lua_module_lcd_touch` | 触摸坐标读取（中断/轮询） | esp_lcd_touch |
| `lua_module_board_manager` | 获取面板/触摸句柄 | esp_board_manager |
| `lua_module_emotion` | 情绪视频控制（emotion.set/get） | emotion_video |

Lua 脚本可通过 `board_manager` 模块获取硬件句柄，通过 `display` 模块进行绘图，通过 `lcd_touch` 模块读取触摸输入，通过 `emotion` 模块切换情绪视频。

## 十一、关键设计决策

1. **不使用 LVGL 作为应用层框架**：LVGL 仅作为 `esp_emote_gfx` 的依赖存在，应用代码通过 `display_hal` 和 `esp_lcd_panel_ops` 直接操作面板，避免引入完整的 GUI 框架开销。

2. **Board Manager 作为统一硬件抽象**：不同板卡的显示硬件差异（DSI/SPI/RGB、不同分辨率、不同驱动芯片）被 YAML 配置 + 工厂函数模式封装，上层代码无需感知硬件细节。

3. **所有权仲裁而非抢占**：采用协作式互斥模型，消费者主动 acquire/release。Release 后所有权变为 NONE（而非自动恢复给某个默认消费者）。

4. **Emote 与 Emotion Video 双轨并存**：传统 emote 引擎（分区内 emoji 动画资源）与新 emotion_video 系统（SD 卡 MP4 视频）同时存在。emote 用于启动早期的离线表情展示和网络状态联动，emotion_video 在系统就绪后接管默认显示，并由 LLM/Lua 通过 capability 动态切换。

5. **PSRAM 双缓冲**：帧缓冲分配在 PSRAM 中，最多 2 个缓冲。DSI/RGB 面板通过 DMA 加速传输，SPI 面板自动处理字节序交换。

6. **Lua 可编程性**：通过 Lua 模块暴露完整的显示、触摸和情绪控制能力，允许用户脚本实现自定义 UI 和情绪切换，无需重新编译固件。
