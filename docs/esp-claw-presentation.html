ESP-Claw

AI Agent 运行时固件架构

Sense → Decide → Act · 完全本地化的设备端 AI Agent

ESP-Claw 是什么？

  • AI Agent 运行时 — 运行在 ESP32 系列芯片上
  • Sense → Decide → Act — 感知→推理→行动，完整的设备端闭环
  • LLM 驱动推理 — 支持 OpenAI / Anthropic / Custom 三种后端
  • Lua 脚本执行硬件操作 — LLM 编写 Lua 代码操控 GPIO、I2C、PWM 等外设
  • 多 IM 平台接入 — QQ、飞书、Telegram、微信、WebIM
  • 语音交互 — TTS 文本转语音 + ASR 语音识别
  • 虚拟角色 — Hiyori 角色动画，10 种情绪表达
  • 17 块开发板支持 — 7 个厂商，YAML 驱动板卡配置

8 层 架构总览

8 IM 通信层 — QQ · 飞书 · Telegram · 微信 · WebIM
7 HTTP 服务层 — REST API · WebSocket · Captive DNS
6 应用组装层 — main.c 启动序列 · app_claw 组装
5 核心引擎层 — ReAct 循环 · 事件路由 · 记忆 · 技能
4 能力插件层 — 19 个可调用工具 (Capabilities)
3 Lua 模块层 — 6 驱动 + 21 功能模块
2 硬件抽象层 — Board Manager · Display Arbiter
1 ESP32 硬件 — LCD · 触摸 · 音频 · 摄像头 · SD · LED

自底向上，每一层为上一层提供抽象。 底层 3 层负责硬件交互，中间 3 层构成 Agent 大脑， 顶层 2 层提供外部通信能力。

FreeRTOS 任务优先级统一为 5，时间片轮转调度。 各模块通过 Queue 进行 IPC 通信。

Event Router

事件总线，6 种动作类型、5 种会话策略。规则 JSON 热重载。

ReAct 循环

取请求→收集上下文→LLM 调用→工具执行→循环。最多 32 轮。

Context Providers

5 个提供者注入：档案、长期记忆、会话历史、技能列表、工具定义。

Outbound Binding

各 IM 平台注册发送函数，Event Router 自动路由到正确通道。

LCD 访问仲裁。非抢占式。动画/视频/LVGL/Painter 串行化。

轻量绘图库。9 种点阵字体 (12-48px)。嵌入式 C 数组。

🔒 Captive DNS

DNS 劫持配网门户。UDP 53 端口。AP 模式激活。

💾 settings (NVS)

NVS 键值存储封装。Wi-Fi/LLM/IM/能力开关持久化。

4. Lua 模块层 — LLM 操控硬件的桥梁

LLM 生成 Lua 脚本 → 调用 C 函数 → 操控硬件外设。每个模块通过 luaL_Reg 数组注册。

6 个硬件驱动 (lua_driver_*)

  • GPIO — 读写、中断、上下拉
  • ADC — 模数转换、校准
  • I2C — 总线读写、多端口管理
  • MCPWM — 电机/舵机 PWM
  • Touch — 电容触摸读取
  • UART — 串口通信

21 个功能模块 (lua_module_*)

  • system · display (LVGL) · camera · audio
  • led_strip (WS2812) · imu · env_sensor
  • storage (FATFS) · ir · button · knob
  • event_publisher · call_capability · board_manager

5. 核心引擎层 — Agent 的大脑

🧩 claw_cap

能力插件框架。JSON Schema 描述符注册。LLM 可见性白名单控制。

🔀 claw_event_router

事件总线。6 种动作类型。5 种会话策略。规则 JSON 热重载。

🧠 claw_memory

记忆系统。FULL (JSONL 结构化) 与 LIGHTWEIGHT (MEMORY.md) 双模式。

📋 claw_skill

技能系统。SKILL.md + YAML frontmatter。动态解锁能力组可见性。

🔄 claw_core — ReAct 推理核心

请求队列→上下文收集→LLM API 调用→工具执行→循环。最多 32 轮。3 种后端。流式响应。请求中断。

claw_core — ReAct 循环详解

  1. 从请求队列取出一条请求
  2. 依次调用 5 个 Context Provider
  3. 拼装消息列表：系统提示词 + 上下文 + 历史 + 当前请求
  4. 通过 LLM 运行时调用远程 API (支持流式)
  5. 解析响应：纯文本 → 回复用户；工具调用 → 执行后回到步骤 4
  6. 最多 32 轮，超过强制终止

3 种 LLM 后端

  • Anthropic — Messages API · thinking 块保留
  • OpenAI 兼容 — Chat Completions API
  • Custom — 任意 HTTP 请求格式

FreeRTOS 任务：栈 16KB · 优先级 5 · 请求队列 4 · 响应队列 4

Event Router + Memory

事件路由器

  • 6 种动作：CALL_CAP · RUN_AGENT · RUN_SCRIPT · EMIT_EVENT · SEND_MESSAGE · DROP
  • 5 种会话策略：新会话·追加·替换等
  • 出站绑定：IM 平台注册发送函数
  • 独立 FreeRTOS 任务：栈 8KB · 优先级 5

记忆系统

  • FULL 模式：JSONL 记录 + 索引 + 小模型自动提取
  • LIGHTWEIGHT 模式：单 MEMORY.md 文件
  • 5 个 Context Provider 供 claw_core 注入
  • 内部独立 LLM 客户端用于自动提取

Capability vs Skill — 关键区别

🔧 Capability (能力)

  • C 函数 + JSON Schema 参数定义
  • LLM 作为 Tool Call 直接调用
  • 两层可见性：enabled_cap_groups (编译) + llm_visible_cap_groups (运行时)
  • 通过 claw_cap 框架统一注册和执行

📋 Skill (技能)

  • SKILL.md Markdown 文件 + YAML frontmatter
  • 告诉 LLM 何时/如何使用 能力
  • 激活时注入正文到 LLM 上下文
  • 动态解锁 cap_groups 的 LLM 可见性

Skill 是说明书，Capability 是工具。激活 Skill → 解锁对应的 Capability 组 → LLM 可以调用这些工具。

7. 应用组装层 — app_claw_start()

15 步组装流程

  1. 检查 LLM 配置完整性
  2. 初始化 Event Router
  3. 初始化 Scheduler
  4. 初始化 Memory
  5. 初始化 Skills
  6. 初始化 Capabilities (app_capabilities_init)
  7. 注册 IM 出站绑定 (5 个平台)
  8. 配置 claw_core + Context Providers
  9. 注册舵机观察者 (可选)
  10. 启动 claw_core
  11. 启动 Event Router
  12. 启动 Scheduler
  13. 启动 NTP 时间同步
  14. 启动 CLI
  15. 发布启动完成事件

关键注册表

  • app_capabilities.c — 能力组注册数组 s_capability_group_entries[]
  • app_lua_modules.c — Lua 模块注册数组
  • app_config — 30+ 字段配置结构体，NVS 序列化
  • 系统提示词 — 角色 AIRI + 对话风格 + 技能规则

main.c — 14 步启动序列

① 分配运行时状态结构体
② 初始化 NVS Flash
③ 从 NVS 加载应用配置
④ 设置系统时区 (TZ)
⑤ 初始化板卡管理器 (LCD/触摸/音频)
⑥ 初始化视频播放器 (扫描 SD 卡)
⑦ 挂载 FATFS 到 /fatfs
⑧ 初始化 Wi-Fi 管理器
⑨ 初始化 HTTP 服务器
⑩ 注册 Wi-Fi 状态回调
⑪ 启动 Wi-Fi (STA + AP fallback)
⑫ 启动 Agent 引擎 (app_claw_start)
⑬ 绑定 WebIM WebSocket
⑭ 启动 Hiyori 表情动画

启动后可选启用内存监控 (每 20s 打印 RAM/PSRAM)，然后进入空闲循环。

10. 构建 与烧录流程

cd application/edge_agent
idf.py build

# 指定板卡
idf.py -DCONFIG_ESP_BOARD_M5STACK_CORES3=1 build

# 完整重构建
idf.py fullclean build

4 阶段构建 + 烧录

  • CMake 配置 — 补丁 · 分区表选择 · FATFS 镜像目标
  • 编译 — 所有组件 + 5 核心引擎 + 19 能力 + 27 Lua 模块
  • 链接 — ELF → BIN
  • 镜像生成 — FATFS 打包 · 分区合并 (bootloader + ota_0 + storage)
# 烧录 + 串口监控
idf.py flash monitor
# 仅烧录 app 分区 (快速迭代)
esptool.py write_flash <addr> build/edge_agent.bin

11. 调试 与诊断

📝 串口日志

ESP_LOGE/W/I/D/V 5 个级别。运行时 esp_log_level_set() 动态调整。

💥 Crash 分析

Guru Meditation → backtrace 地址 → xtensa-addr2line 解析函数名和行号。

💾 Core Dump

16/32MB Flash 存储崩溃现场。idf.py coredump-info / coredump-debug (GDB)。

📊 内存监控

每 20s 打印内部 RAM + PSRAM 使用量和任务栈高水位。

event_router · wifi · lua exec · mcp discover/connect
